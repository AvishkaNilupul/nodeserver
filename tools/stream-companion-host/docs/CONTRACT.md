## Internal protocol (POST JSON)

- `/internal/sync`: `{channel,connected,ready,playback:{status,checkedAt},seed:[{channel,streamId,kind,textKey,replyId,at,delivery,coordinationId?}],pendingCompletions?}`. Public account is bound by token. ready means eligibility for automatic sends from fresh browser state; connected separately allows manual drafts. Presence expires after45000ms. Seeds are own history hashes only, max256. Response `{ok:true,snapshot}`.
- `/internal/reserve`: `{requestId,channel,streamId,kind,textKey,replyId,replyAt?}`. Actual helpers supply the incoming target timestamp when replyId is present; targets expire after45000ms both in fairness selection and at begin. requestId is bound to the full immutable proposal, unique for this attempt; an identical retry is idempotent. Response `{ok:true,reservationId,expiresAt,snapshot}` or `{ok:false,code,reason,retryAt?,snapshot}`. Shared normalized duplicates within one hour and topic/incoming-message duplicates are suppressed. One unused leased permit per channel; eligible waiting clients get fair turns, with direct replies higher priority than generic questions. An unused leased permit expires after20000ms. Until begin, it is not an actual attempt. Submitting/unknown ownership retains its own opportunity and channel spacing without monopolizing unrelated future turns indefinitely.
- `/internal/begin`: `{reservationId}`. Response `{ok:true}` or a not-submitted hold `{ok:false,code,reason}`. Validate token ownership, presence, host pause, current permit and expiry; atomically mark submitting and record the contribution before authorizing one Twitch request. Submitting/unknown never auto-expire into retryable permission. A repeat begin is denied, never a second send grant.
- `/internal/finish`: `{reservationId,delivery,submitted}`. delivery confirmed/rejected/unknown/cancelled. Cancelled requires submitted:false and means the helper certifies no Twitch request. Preserve known confirmed states against downgrade; idempotent completion. Confirmed/unknown keep duplicate ownership; rejection/cancellation release duplicate ownership, with rejected still counting channel budget. Helpers durably queue completion locally before trying network delivery; replay is idempotent. A host outage after confirmed Twitch delivery must not relabel it unknown.

snapshot shape: `{available:true,paused,reason,textKeys,topicStreams,replyIds,accounts}` (existing planner keys unchanged). A disconnected client snapshot still includes registered companion accounts. Client caches snapshots per channel and reports available:false on host outage/staleness. Host unavailable means no Twitch request, explicit suppression/retryable pre-submit cancellation and no send budget. Do not fall back to helper-side DB writes.

Remote coordinator interface for helper adapter: synchronous `snapshot(channel)` cached; async `refresh({channel,connected,observation?})`; async `reserve({account,channel,text,streamId,kind,replyTo})`; async `begin(reservationId)`; async `finish(reservationId,delivery)`; `seed(history)` caches own hashes for next sync; `register(account)` checks own binding; `close()` stops timers/flush loops. All request URLs fixed to127.0.0.1:8795, with test-only injected fetch/base URL. Bounded network timeout1500ms, no redirects. reserve failure returns ok:false; begin failure returns ok:false. No tokens in errors. Add coordinationId to durable helper attempts for seed idempotency. Refresh before own paired status response, and transmit sanitized fresh browser observation from extension getState/refreshChat; never include public chat bodies. Manual drafts remain possible with connected state; automatic proposals require ready:true.

## Browser UI

GET `/api/status` same-origin only, response `{version,updatedAt,paused,host:{health,uptimeSeconds},policy:{channelGapMs,maxAttemptsPerHour,leaseMs},clients:[{id,name,account,channel,connected,ready,online,lastSeenAt,playback,lastDecision,pendingCompletions}],channels:[{channel,nextTurnAt,attemptsLastHour,activeSpeaker,waiting:[{account,kind,reason}]}],events:[{id,at,account,channel,type,reason,delivery?,kind?}],csrfToken}`. Dates ISO or null, counts numbers. All identifiers/text treated as data; DOM uses textContent. GET `/health` returns `{ok:true,version:'1.0.0'}`. GET `/`, `/app.js`, `/style.css` static allowlist with strict CSP.

POST `/api/control` same-origin, JSON `{paused:boolean}`, X-CSRF-Token equal current status csrfToken; persistent global coordination pause/resume only. It cannot authorize Twitch, change browser settings or unpause a helper. No cookies, CORS grants, remote assets, forms, network proxy or secret transmission to UI.
