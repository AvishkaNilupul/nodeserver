## Implementation agreement

- Add a host-owned director/bank/history module sharing HostStore's existing connection and transaction boundary. Keep the existing contributions, permits and exchange ledger; imported or new canonical history must link to them without charging an attempt twice. Normalized messageKey remains duplicate identity; exact offered text is separately immutable and checked byte-for-byte.
- The central bank includes greeting, topic, recognized reply-category and paired-exchange entries with fixed account assignments. Seed current defaults once. The UI edits one catalog under an optimistic whole-bank revision; a saved revision is immutable. Existing exchange scene identities and consumption remain valid. Replacing paired text creates a distinct durable scene identity; reverting to identical old text cannot bypass consumption. No general template language: only the current game/category substitution and the host-generated partner mention.
- Host-issued automatic offers contain an opaque planId and authorityEpoch, exact account/channel/broadcast, kind, participation/opportunity identity, exact text/category, optional replyId/author/time, bank/profile revision, notBefore/expiresAt and current control-generation/session/settings-revision binding. The backend owner finalizes the exported schema here before dependent modules consume it. A bank save affects future decisions, never rewrites a reserved/submitting payload; unused work may be cancelled and reconsidered only where no-send is proven.
- Helpers report their own bounded EventSub messages and inspected stream metadata, plus validated browser playback/armed state and control binding. Do not use browser-echoed incoming chat or live metadata as the planner's source of truth. Incoming bodies are temporary bounded planning observations, not a new retained incoming-chat archive.
- Central planning handles mention priority, supported conversation, greeting/topic selection and existing paired offers. The browser does no competing local automatic planning or AI/phrase fallback. Existing final helper identity, target freshness, restriction/shared-chat, follower hold, Stop/Pause and reserve→durable local attempt→begin→final guard→provider→durable completion remain mandatory. Explicit drafts and manual reviewed sends also pass through central content/history authority; optional AI may use a local helper as a provider adapter without moving its secret to browser/cloud.
- Before arming central authority, import each registered helper's exact available outgoing history and each paired extension's sent/participationAttempts/handled ledgers through bounded authenticated pages. Per-source IDs/digests and durable page/final acknowledgements make retries idempotent. Account-bound missing/failed imports hold automatic sends. Do not infer unattempted from missing old helper text; preserve browser-only handled/no-match and pending/unknown/rejected tombstones independently of retained outgoing text. Legacy hash-only records remain explicitly text-unavailable. Preserve source journals and completion outboxes.
- Central automatic reserve requires the host-issued plan identity and exact binding. Old autonomous proposals cannot become a fallback after the authority switch. A lost/uncertain begin/provider/completion outcome never creates a second send grant. Late provider confirmations enrich the same canonical history row monotonically.

## Exported protocol v1 (implementation contract)

The installed host starts HostStore with `directorEnabled:true`; legacy coordination-only fixtures explicitly omit that option. All director methods share its connection and transaction helper. Automatic authority is held until both authenticated sources (`helper`, `browser`) have completed for every registered client (eight acknowledged sources for the four-profile roster). Incoming observations exist only in memory and expire after45 seconds. Restart changes the authority epoch, cancels unused plans and clears observations; submitting/unknown permits and consumed opportunities remain.

Bank is exactly `{entries,profiles}`. Entries are exactly `{id,kind,category,lines,accountIds,enabled}`:1–128 entries, unique lowercase IDs1–80 characters `[a-z0-9_:-]`, kinds `greeting|topic|reply|exchange`,1–16 lines (exchange exactly2),1–260 characters per line, finite nonempty profile assignments, boolean enabled. No commands, links, multiline/control text or arbitrary substitutions. Topic categories are `general|just chatting|music|art`; greeting/exchange category equals kind; reply categories are `greeting|checkin|goodday|roughday|quietday|thanks|farewell|goodnight|welcome|dayfollowup|reciprocal|quietfollowup|dayplans|capabilities|automation|game|streamtitle|livestatus`. Only topic `{game}` and reply metadata `{game}`/`{title}` are substituted, then the final300-character send validator runs. Profiles exactly cover `primary,test,third,fourth` and contain `{id,chatMode:'mentions'|'participate',replySource:'local'|'ai'}`. Serialized bank max60000 UTF-8 bytes. Whole-bank saves use CAS revision and immutable request identity; identical request replay returns its original result, changed payload under that ID rejects409. Exchange content identities survive edits and reverts independently of entry display IDs.

Public GET `/api/director` returns `{protocol:1,updatedAt,ready,reason,revision,bank,profiles,plans,history,nextBeforeId,imports,lastMutation,csrfToken}`. Profiles expose `{id,account,chatMode,replySource,revision,imports:{helper,browser},ready,reason}`; imports expose `{accountId,helper,browser,complete}`. Plans expose only `{planId,accountId,account,channel,streamId,kind,text,category,source,state,notBefore,expiresAt,reason,cancellable}`. History rows expose `{id,accountId,account,channel,streamId,kind,text,textAvailable,delivery,source:'central'|'legacy',at,updatedAt,submitted,messageId,reason,replyTo,category}`. `text:null,textAvailable:false` is honest legacy missing text. Public output never contains bindings, authority epoch, migration transfer IDs or incoming bodies. `lastMutation:{requestId,revision}|null` reconciles uncertain saves. Cancel returns `{ok:true,planId,state:'cancelled'}` and permits only unused proven unsubmitted work. Fixed history pages `/api/director/history/{all|primary|test|third|fourth}/{beforeId}` return `{history,nextBeforeId,csrfToken}`, max50 rows; beforeId0 means newest. No query string is accepted.

Account-bound internal POST methods (same existing client-token guard):

- `/internal/director/import`: `{source,importId,page,final,digest,records,preferences?}`. Source helper/browser; sequential page0+; max50 records; digest is SHA256 of `JSON.stringify({records,preferences:preferences??null})`. Each record has stable `recordId` and type `history|participation|handled`. History carries own existing outgoing fields; participation carries `participationKey` and routing/kind/time/delivery/submitted; handled carries its existing `account:channel:messageId` key. No unknown source fields are persisted. Preferences `{chatMode,replySource}` appear only on final browser page and seed once. ACK `{ok:true,source,importId,page,digest,complete,nextPage}` is durable/idempotent. Existing coordinationId is merged, never double-charged.
- `/internal/director/observe`: exactly `{protocol:1,binding,armed,streamContext,messages,restrictions}`. Binding is `{generation,sessionId,settingsRevision}`. Messages/stream metadata/restrictions come from the helper's own EventSub/inspection; playback/channel/connection remain the existing authenticated sync facts. Restrictions exactly `{sharedChat,emoteOnly,subscribersOnly,sendHeld}`. Return `{ok:true,director}`.
- Internal director projection is `{protocol:1,authorityEpoch,ready,profile:{id,chatMode,replySource,revision},bankRevision,plan?,generation?,reason}`. Exact plan is `{planId,authorityEpoch,clientId,account,channel,streamId,kind,participationKey,opportunityKey,text,textKey,exactKey,category,source:'automatic'|'manual',replyId,replyAuthor,replyAt,bankRevision,profileRevision,notBefore,expiresAt,binding}`; exchange additionally carries exchangeId. Normalized textKey is unchanged; exactKey separately hashes exact UTF-8 text. No helper may alter offered text/routing/binding.
- `/internal/director/draft`: `{requestId,binding,mode:'reply'|'summary'|'phrase',category?}`; category only/required for phrase. Return `{ok:true,director,draft?,generation?}`. Draft is `{text,summary?,category,reason}`. No draft sends automatically.
- `/internal/director/manual`: exactly `{requestId,binding,text}` creates an exact reviewed manual plan, returning `{ok:true,director,plan}`. No direct provider request occurs.
- `/internal/director/preferences`: exactly `{requestId,chatMode,replySource}` updates only this authenticated client's central preference after an explicit native settings edit. Stale observations cannot call this implicitly. No-op preference changes preserve the current revision.
- `/internal/director/generated`: exactly `{requestId,generationId,binding,result:{text,summary?,reason}}`. Generation request is `{generationId,requestId,mode,account,channel,target:{id,author,text,at}|null,binding}`. Existing private helper composer performs AI work outside the host transaction using its own current source input. The host fences results against original generation, target, profile/bank revision, binding and fresh observations, then freezes text or consumes no-match. No automatic local fallback.
- Existing reserve retains its existing fields and adds `{planId,authorityEpoch,text,binding}`. Director-required runtime rejects old no-plan proposals. Begin for a director permit additionally requires `{planId,authorityEpoch,binding}` and still authorizes only once. Finish preserves existing fields and optionally adds `outcome:{at,messageId,reason}`; no fresh binding is required for durable late completion replay. Canonical text/routing always come from the host plan.

Existing explicit Start/settings controls update central profile preference after the paired helper accepts the command; stale observations never write preferences. Browser import preferences seed only if no earlier central preference was saved. Public account sent history is projected from the same central rows, while control-command diagnostics remain separate.

Before page0, each source freezes its migration pages and preferences in its own existing trusted storage. A restart resumes those exact bytes and transfer identity until the durable final ACK; recomputing a partially imported manifest from changed arrays is invalid. Completed imports do not restart. Later known delivery outcomes use existing completion replay and canonical permit identity.
