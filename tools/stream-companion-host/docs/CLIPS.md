# Viewer clips contract

The controller creates Twitch viewer clips manually or from observed third-party chat reaction bursts. It does not analyze video or audio. Trigger text must say "Chat reaction detected". It never adds chat posts or clip views. Both companions share one host journal and one creator per moment.

## API and module boundaries

- Helper: paired POST `/api/clips/status` `{}` -> `{ok:true,account,authorized,jobs}`; `/api/clips/create` exact `{requestId,channel,streamId,source}` (manual|automatic) -> `{ok:true,job}` immediately; `/api/clips/authorization` exact `{action:"start"|"poll"}` -> `{ok:true,...device-flow public fields}`. No client IDs/tokens supplied remotely. Start authorization requires held/disconnected companion. Only this explicit flow requests `clips:edit`; preserve chat scopes and old grant until a matching new grant succeeds. No silent OAuth approval.
- Jobs: `{requestId,account,channel,streamId,source,createdAt,updatedAt,state,clipId,url,error}`. States queued,submitting,pending,confirmed,failed,cancelled,unknown. Persist before Twitch Create; no POST retry, including restart or uncertain response. Known clip IDs may be checked for up to60s. URLs only canonical https://clips.twitch.tv/<id>, confirmed by Get Clips with matching creator/broadcaster IDs. Helper job journal private0600 and bounded. Restart marks no-ID queued/submitting as unknown; resumes GET only for known IDs. A durable write failure prevents Create.
- Host accounts adapter: `clipStatus(id)`, `clipCreate(id,body)`, `clipAuthorization(id,body)`; validate/sanitize public shapes and errors with existing private-value cleaner.
- Host `createClipController({db,accounts,isPaused,now,...})` returns `snapshot()` sync, `configure(body)`, `create(body)` async, `authorize(body)` async, `tick()` async, `start()`, `close()`. SQLite tables separate from existing chat tables. Never changes chat intent. Background tick every5s, independent of page reads. Persist global journal before helper request. On uncertain helper response reconcile only with status; never resend Create. Restore pending known helper request IDs by status reads only.
- Public GET `/api/clips` -> `{ok:true,settings:{enabled,channel,accountIds},accounts:[{id,account,available,authorized,error}],jobs:[...job plus accountId/reason],detector:{state,reason},updatedAt,csrfToken}`. Latest50 jobs only.
- Public POST `/api/clips/settings` exact `{enabled:boolean,channel:login,accountIds:["primary"|"test"]}`; nonempty unique <=2.
- Public POST `/api/clips/create` exact `{requestId,channel,accountIds}`. Both selection means ONE eligible creator, not duplicate clips. Live streamId comes from fresh host snapshot, never browser input.
- Public POST `/api/clips/authorization` exact `{accountId:"primary"|"test",action:"start"|"poll"}` -> public device flow fields only (`verificationUrl,userCode,pollAfterMs,pending,authorized,account`). POST results include ok:true. All routes retain same-origin,CSRF,remote superadmin/2FA and finite allowlists.

## Gates and detection

Automatic clips require explicit channel/account opt-in, central coordination resumed, selected companion connected and not held, fresh heartbeat<=45s, watch playing on same channel checked<=15s, current live streamId/context<=90s, clips:edit and no command pending. Manual clips require the same live/playback/permission checks but may work while chat or central coordination is held, because the click is explicit. Final helper gate rechecks selected account/channel/stream and watch freshness immediately before Twitch POST. Stop or channel changes during preparation cancel any unsubmitted job. Immediately before automatic submission the helper requests a single-use `/internal/clips/permit` using its existing private host pairing; it is bound to the host job, creator, stream and age. Changing clip settings, pausing, host restart or an unavailable host invalidates pending permission. No such route is exposed through the remote gateway.

Observe fresh feeds for90s after start/reconnect/stream change. Merge by message ID, exclude both companion usernames. Last20s requires>=8messages,>=4authors,>=3authors using a reaction term; rate>=3x preceding baseline, newest qualifying message<=10s. Ignore old backlog and malformed/future data. Deduplicate overlapping events. Shared cooldown10min and max3attempts/hour/channel includes uncertain and rejected attempts. Manual clicks share cooldown (report existing job) and never bypass an in-flight clip. Restriction failures do not switch to the other account automatically. No queued moment is replayed when a stream/account comes back.

## UI

A Clips panel on overview and account pages: channel + Main/Second/Both selection, Clip moment, explicit Auto clips setting/save, permission status and Enable clips per account; display Twitch activation code/link and poll only after explicit start. Explain authorization pauses the account and requires approval on Twitch. Show detector reason, creation/confirmation/unconfirmed state, creator and clip link. Use native links/textContent, no embedded playback or extra remote assets. Avoid accidental creation on polling/page load/selection. No live clip creation during development tests.

Official reference: https://dev.twitch.tv/docs/api/reference/clips#create-clip (2026-11-25); requires clips:edit, live eligible viewer and stream clipping enabled. Asynchronous confirmation may take60seconds.
