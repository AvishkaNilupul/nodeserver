## Contract for this change

- Host alone schedules a maximum two-line exchange, only for exactly two active participation clients on the same fresh live broadcast. Feature has a persisted `exchangesEnabled` control (default false; enable after activation). Normal central Pause and individual Stop take priority. Any missing/stale/paused/disconnected partner or broadcast change cancels that exchange. No catch-up burst after restart.
- Sync adds `exchangeContext:{streamId,checkedAt,lastHumanAt}` from the extension's current live metadata and observed public chat, only when participation is armed. No raw incoming chat is sent to host. Both clients need current metadata and playback. Human activity in the last90s defers offers. Real mentions/conversation opportunities retain priority in the extension and host.
- Persist next eligible time with randomized60–120minute spacing, and second line3–6minutes after confirmed first delivery. Never bypass existing shared3minute gap, six/hour, per-account10minute participation spacing, or live/moderation checks. Full exchange deadline20minutes. First scheduled after warmup, not immediately on enable/start. Timer state survives restart. Uncertain or rejected first delivery ends the exchange; only confirmed first delivery may lead to line2. At most one active exchange/channel.
- Curated safe local scenes; no invented observations about video, personal history or human identity. Alternate initiators. Persist used scene IDs per channel and never reuse a used scene. Exhaustion stays quiet. Record consumption before permission to post so a crash cannot duplicate a line. A cancelled exchange's already-used scene stays consumed.
- Snapshot adds optional `exchange:{id,account,channel,streamId,key,text,notBefore,expiresAt}` for this client when its line is due. `id` is an opaque turn ID; `key` is `exchange:${id}`; both lines have distinct IDs. Exact account/channel/stream/text and due state must be validated at reserve and begin, using the expected curated text fingerprint. Host keeps scene IDs, hashes, outcomes and routing metadata, no raw incoming chat or Twitch credentials.
- Reserve adds optional `exchangeId`; valid only with kind=`exchange`, streamId=current broadcast, no replyId. Bind exchangeId into immutable request identity. Adapter forwards this field. Twitch helper accepts kind exchange only with a participationKey and matching exchangeId, still performs normal live inspections. Send via plain tagged @mention text, **not** a fabricated Twitch reply target. Unknown delivery never retries. All actual sends still require the existing reserve→begin→finish protocol.
- Public `/api/control` accepts exactly one of `{paused:boolean}` or `{exchangesEnabled:boolean}` under existing same-origin/CSRF protections. Public status adds `exchanges:{enabled,intervalMinMs,intervalMaxMs,replyMinMs,replyMaxMs,channels:[{channel,state,nextAt,reason,usedScenes,totalScenes}]}`. No forced-send or fast-forward live endpoint.
- UI adds a clear enable/disable control, tagged-message explanation, schedule/wait reasons and scene usage. Existing stale/control-race behavior applies. Default disabled until root verifies tests, installs both adapters/extensions and explicitly enables it. Keep second personal profile paused unless otherwise requested; new exchanges wait until both are started.
