# Fourth proof renewal and socket-close diagnosis

A paired fake-clock reproduction found an avoidable renewal gap: a one-second poll with a strict two-second age threshold can start renewal at age three seconds. A successful2.5-second country check then finishes after the unchanged five-second helper proof deadline. The helper correctly closes the socket. The immediate publication poll restores readiness but cannot resurrect that socket. This demonstrates a timing edge; it does not establish the cause of any live disconnect.

The fourth browser now schedules one cancellable renewal timer for1000ms after each successful proof. Probe timeout stays3500ms and the helper's proof expiry stays5000ms. Probes remain single-flight. Successful proof publication is immediate; a pending publication survives an already-running poll and runs once that poll finishes. Timer and publication work are fenced by worker version/epoch and cancelled on reset/Stop. A late response cannot publish or submit retired work. Failure/non-USA still resets and closes resources. No Twitch request, uncertain-send retry, direct fallback or guard relaxation is added.

The helper caches `lastSocketClose` as `{source,at,code,wasClean}`. Sources are only `browser-close`, `browser-error`, `proof-expiry`, `lease-expiry`, `local-reset`, `local-close`, `setup-timeout`, `command-failure`. Timestamp is local epoch milliseconds; code is a bounded close code and wasClean a boolean. The first finish records before callbacks. Cascaded cleanup during that close callback cannot overwrite its initiating cause; a later independent close may replace it. The cache survives ordinary reconnects and contains no socket/account/session IDs, URLs, raw reasons, addresses, tokens or payloads.

The existing bounded USA health logger explicitly projects this cache. New close timestamps count as state changes even if routing has already recovered by the next five-second sample. Original proof timestamps still do not create extra state-change rows. Existing four-file1MiB rotation/0600 limits and error isolation remain.

Tests use the actual browser/helper relay modules with paired fake time, synthetic US/non-US responses and no real sockets or requests. They cover2500ms and3499ms success, overlapping publication, bounded timeout/non-US/failure, Stop/late results, strict five-second expiry, source attribution and callback-cascade retention. Runtime rollout is separate: preserve every private file/manifest key and use normal Stop/Start with reviewed source fingerprints; no live rollout is part of this source change.
