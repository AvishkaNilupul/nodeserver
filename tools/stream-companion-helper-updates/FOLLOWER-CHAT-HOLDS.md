# Follower-only room requirements and account send holds

`follower_mode` describes a room rule, not whether the authenticated account satisfies it. Channel inspection preserves the flag and valid required follow duration as information; it does not claim the account follows and does not reject Start only for this rule. Other offline/shared/emote/subscriber gates remain unchanged. No additional scope, follow action, native click, eligibility probe or extra chat message is introduced.

The next normal intended message uses Twitch Send Chat Message. A confirmed response remains confirmed. A `followers_only_mode` rejection consumes the existing attempt/budget once and adds a separate owner-only durable account/channel chat-send hold. This journal contains only validated account/channel, a fixed code, a timestamp and a held/cleared record; it never adds fake history attempts. Missing journal initializes empty; malformed/unwritable state fails closed. Real rejected history can recover a missing newer hold without resurrecting a rejection older than an explicit clear.

While held, the helper refuses before chat reservation/provider work, and the extension refuses before planning, drafting or manual send. Watch checks, chat reads and metadata continue. Coordination receives `autoReply:false` and no exchange context for the held account. Public status may include `sendHold:{account,channel,held,code,reason,at}` with fixed safe reasons; existing activity shows the waiting reason. No cookie/token/provider response is exposed.

Only a valid explicit owner Start command or native Connect can clear the selected account/channel hold. A failed clear keeps sending held while read/playback may still connect. Clearing occurs after identity/channel preparation and a current generation/session/command guard, immediately before connection. Automatic recovery, network reconnect, helper restart, browser reload, settings saves and Stop do not clear it. A per-account/channel revision prevents a late response from an older Start generation from reinstating a hold after a newer explicit clear. A late rejection after Stop still records the real rejection and hold; Stop never re-arms anything.

Tests must cover eligible follower-room Start and confirmed normal message; the first denied/too-recent-follower response and all later message categories/manual sends without new attempts; persistent recovery; storage errors; channel/account isolation; explicit Start/native Connect clearing versus automatic reconnect/reload; Stop and late-response races; and retention of all other gates and unknown-delivery behavior. All checks use fixtures, not real Twitch posting.

Official references: https://dev.twitch.tv/docs/api/reference/chat#send-chat-message ; https://dev.twitch.tv/docs/api/reference/chat#get-chat-settings . Exact follow-date inspection would require a separate `user:read:follows` grant, which this change does not request.
