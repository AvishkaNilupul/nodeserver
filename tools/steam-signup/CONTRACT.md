# Steam signup contract

One active signup at a time in a dedicated private Chrome window. Start and Resume are explicit actions. A regional queue holds one signup per selected country in page memory; reloading the page drops it. Start authorizes the displayed Steam agreement and account creation. The helper clicks the initial CAPTCHA checkbox, accepts the agreement, submits Continue only with a real CAPTCHA response, and submits Done only after Steam validates the credentials. Only image or puzzle challenges require operator input. An error stops the queue and preserves the current identity.

Each signup requires a matching-country sticky residential proxy. The browser's observed IP and country must match the prepared exit before any Outlook inbox is reserved. Credentials are sent only to the configured proxy's challenges for the assigned tabs. Apply proxy settings only to the private session and clear them on completion/window close. No other private windows may exist when starting.

The original Outlook server atomically reserves an inbox with no other use, exclusively for Steam. Interrupted signups retain that inbox; there is no automatic replacement address. Credentials live in the encrypted local vault. Browser session storage holds the active session; page scripts receive only their assigned identity, never proxy credentials.

Record requested country, observed proxy location, and Steam's signup country separately. Store country remains unverified until independently observed in Steam. Generated phone/address records are explicitly sample data, match the requested country, and are not submitted as real contact details. No marketplaces from this app. Server upload (owner's request, 2026-11-01): each finished account is queued and sent to the admin site's Steam accounts page through `cloud-sync.cjs` → `cloud-import.cjs` over the deploy SSH key, account on stdin, insert-only on the server. Sample contact details and the proxy IP stay here. Contract: docs/STEAM-ACCOUNTS.md.

The browser investigation confirmed that Steam's password-availability state is enabled by the password field's inline keyup handler. Filling only input/change events leaves that state false and triggers a local rejection before any creation request. Dispatch the normal keyup event, keep the native validation flow, and never force the site's internal availability flags.
