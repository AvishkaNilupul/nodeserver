# Valorant account stock

`/valorant-accounts.html` is a superadmin page behind the application's existing 2FA gate. Its API is under `/api/valorant`. The page shows signup attempts, completed accounts, requested country, observed proxy country, expected shard, independently verified country/shard, Riot ID, level, rank, skins, agents, verification status and sale references. Unknown progression remains null, distinct from a measured zero. Credentials are encrypted with `secretBox`, excluded from normal model selections and public rows, and revealed only on an explicit authenticated request with no-store caching.

The local creator uses `tools/valorant-signup/cloud-sync.cjs` over the existing private SSH transport, with one account on stdin. Its private `cloud.json` has the same shape as the Steam creator's configuration and stays in macOS Application Support. `cloud-import.cjs` imports into `valorantaccounts`; unique local ID and normalized username prevent duplicate rows. A reserved identity is `signup_pending`, not completed inventory. A later successful signup promotes only its matching pending row. Retries never replace a listed/sold account or overwrite operator notes and checks. Uploading a pending row does not suppress the later completed upload.

Account checks require successful login, verified email, observed residence country and observed VALORANT shard with a recorded check source. These are separate from the signup proxy and predicted shard. Listed/sold records cannot be hand edited through the stock editor. Pending signups cannot be verified as completed accounts.

`POST /api/valorant/eldorado/check` checks game 32 (Valorant), Account category, through `eldoradoAccountOffers.epicPermission('32')` in the live application process. It persists category restriction, seller high-risk permission, check time and canSell. It does not publish, change marketplace settings, or refresh an independent seller cookie jar. Unknown permission stays unknown; a rejected category is shown as unavailable. The page does not substitute another game's category. No trial offer exists until real completed stock and seller category access are confirmed.

The initial rollout provides stock management, creator upload and category access checks. Publishing and buyer delivery must be integrated after the category and real stock checks succeed; the page does not expose an unimplemented Publish button or claim an active selling engine. The request to start a small Eldorado trial remains open until an actual offer is published and read back.

Validation: `node --test tests/valorantAccounts.test.js tests/valorantSignup.test.js`. Deployment follows the repository's targeted-copy rules: preserve live server/navigation bytes, back up, apply only this route/mount/navigation/assets/importer, load-check, fingerprint and restart the main app once.
