# Dedicated Twitch Rewards farm

Twitch Rewards → Farm bots (`/twitch-rewards.html#farm`) controls an isolated GTA VI worker. Each bot owns up to 20 verified idle pool accounts and has independent Start/Stop controls. Ordinary no-claim, managed, rental and marketplace services are not reconfigured by this feature.

The section uses a separate container prefix, source/image and persistent Configuration/log folders. It requires the TwitchDropsBot `codex/gta-vi-reward-farm` build, image `twitch-reward-farm:20261120`. RewardCampaignsOnly prevents fallback to standard Drops. ClaimDrops stays off. The configured campaign window ends 2026-12-01 07:59:59.999Z; both worker and controller enforce the cutoff. Stop retains the account reservation. Creation is capped at ten containers and 101 accounts across operators. The owner authorized 95 additional accounts on 2026-11-20 while keeping 150 pristine accounts reserved for paid orders.

Creation respects both existing fleet fences, committed listing ledgers and the pristine-account reserve. It atomically claims a pool row, validates Twitch login/ID against the token, writes a guarded private config and creates a stopped container. It returns a failed claim only when Docker proves no corresponding container exists; otherwise the account stays reserved for review. Accounts with sold-game history, committed listing ledgers or earned-unclaimed inventory are excluded. Idle accounts with previously claimed drops are reused before pristine stock. OAuth identity and live inventory are checked per account. Pristine supply is counted again after each pristine claim; a batch that would cross the reserve is rolled back.

A minute worker check reads only this section's containers and imports issued code receipts into the existing encrypted Accounts & codes ledger. Import verifies account identity, deduplicates codes and rejects overwriting a saved code. There is no public worker-auth endpoint. Private SSH transports may carry decrypted code exports internally; they must not be logged. Code files and keys remain persisted in each bot's private Configuration mount as a recovery source.

Watch progress is only shown when Twitch reports it. Missing counters remain unknown. A badge goal is not a game code, and surprise game keys are not guaranteed after a viewing timer. Account/code totals count actual saved awards, not viewing activity.

Deployment is targeted: fingerprint the five existing Rewards assets/router before copying, back them up with a manifest, install only this section's changed/new files, require-load the route and run syntax checks, restart the app, verify unauthenticated APIs remain protected and run an authenticated smoke through the documented throwaway Express harness. Build the separate worker image; never overwrite existing farm image tags. Add/start at most 20 accounts in a wave and verify live behavior/capacity before the next wave. Every create/start requires at least 7 GiB available (a 1 GiB container budget plus 6 GiB headroom), and refuses a saturated CPU load. Grouped bots retain each account identity, reservation and progress separately, including scoped code attribution. The legacy one-account pilot remains compatible.

Rollback: stop this section's exact reward containers first; retain their folders, keys and pool reservations. Restore existing files from the deploy manifest and remove only its newly installed feature files, then restart the app. Keep the reward-bot collection and code receipts. Do not return accounts to available while any config can still use them.

Grouped creation also excludes renter-owned tokens, non-returned reseller accounts and non-dry-run active/planned auto-farm assignments. Historical non-GTA code receipts on reused accounts remain in encrypted worker storage and are skipped by GTA-only dashboard sync; they do not block later GTA receipts.
